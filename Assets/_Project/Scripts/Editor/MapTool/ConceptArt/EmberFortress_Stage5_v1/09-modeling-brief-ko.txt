1. 아트 방향과 실제 데이터
사용자가 제공한 FIVE REALMS 지도5번 EMBER FORTRESS를 기준으로 한다.
식은 현무암의 보라회색, 어두운 철재, 청동 보강재, 붉은 깃발, 주황 용암과 작은 황금빛 포인트.
컨셉샷: 식은 암반 입구 → 현무암 발판 → 철제 다리와 용암 협곡 → 요새 외벽/정문.
밟을 수 있는 상면은 평탄한 비발광 암반/철판으로 읽힌다. 용암은 틈과 수로에 한정.
현재 Data/StageLayouts에서 W5*.json은 발견되지 않았다. 01은 분위기와 조립 예시이며 실제 점프 거리나 좌표를 검증한 레벨 설계가 아니다.
보스 전용 모델은 이번 요구 범위가 아니다. M01~08은 일반/정예 몬스터8종의 디자인이다.

3. 확인된 맵툴 기능과 연결 계약
- StageLayoutData는 ground/platform/wall 사각 블록, 체크포인트, 코인, 특수 수집물, 가시, 이동 발판, 적, 낙하물, 장식, 작동형 가시, 스위치, 문, 보스를 지원.
- Unity X/Y 평면 진행, Z 깊이. BlockDepth=4m.
- 블록 x/y는 좌상단, y가 표면이고 몸체가 아래로 연장.
- 지형 코어2x2x4m, 공중 발판3x1x4m, 얇은 덱3x0.4x4m.
- StageLayoutBuilder.Theme은 기존 판정용 오브젝트 아래 아트를 붙이고 기본 렌더러만 숨긴다. 아트의 콜라이더는 비활성화된다.
- groundCore/groundEndLeft/groundEndRight/rockCore 및 변형 배열, floatingPlatform/timberPlatform.
- 체크포인트/골인/이동발판/낙하물/가시/압력판/문 등의 아트 슬롯 존재.
- decorations는 prop,x,y,z,rotY,scale. z=-9999 미지정일 때 PropTable defaultZ를 사용.
- PropTable Implemented 행 및 실제 프리팹이 있어야 배치 가능.
- 0.25/0.5/1m 격자, JSON 저장·검증·씬 빌드 흐름.
- enemies는 MonsterTable 숫자ID. M01~08은 제작용 ID이며 런타임 등록ID가 아니다.
- ThemeKitTool 자동 탐색 접두어: T01_~T04_, T06_, T07_, G01_, G02_, G03a_, G03b_.
  G03~G06 제작ID를 자동으로 기믹에 연결하지 않으므로 수동 슬롯 설정 필요.

4. 치수·피벗·파일 이름
1 Blender unit=1m. CSV W/H/D는 Unity X/Y/Z.
Blender X=폭, Z=높이, Y=깊이로 모델링. FBX 후 Unity X진행/Y위/Z깊이를1m 큐브와 첫 지형으로 확인.
축 변환을 두 번 적용하지 않고 루트 스케일1, 회전/스케일 적용. 움직이는 파츠 피벗은 보존.
top-left: Blender 원점(0,0,0)이 좌상단/깊이중앙. 메시 범위 X=0..W, Z=-H..0, Y=-D/2..D/2.
bottom-center: 바닥Z=0, X/Y중앙0. body-center는 비행체 중심. emitter는 효과 발생점.
시트02의 'local Y'는 Unity 상하축, Blender에서는 Z에 해당.
CSV의 기존 지형 규격 외 크기와 삼각형 수는 권장치이며 실제 카메라/캐릭터에 맞춰 조정.
예산은 최종 triangles. LOD1 약50%, LOD2 약25%부터 실루엣을 확인.
전역 PropTable ID는 EF_T01_CooledBasalt 등 EF_ 접두어를 사용해 이전 테마 ID와 충돌하지 않게 한다.
테마 자동 탐색용 프리팹 파일명은 T01_EF_CooledBasalt.prefab처럼 T01_ 접두어를 유지.
새 모델은 EmberFortress 폴더에 저장하며 기존 초원/사막/설산/해안 에셋을 덮어쓰지 않는다.

5. 지형 제작
T01/T04/T05의 좌우 접합 프로파일은 동일. 빌더의 코어 변형과 좌우 미러링 후에도 틈이 없어야 한다.
T02는 왼쪽 노출/오른쪽 접합, T03은 반대. 모서리 장식이 이웃 면을 침범하지 않게 한다.
T04는 반복 적층용이며 매 층마다 띠나 강한 용암 줄무늬를 만들지 않는다.
T05의 상면은 로컬UnityY=0, 포장 두께를 높이2m 안에 포함. 정면 청동 띠만 분리.
T06 하부 돌출은 전체1m높이 안에 넣고 콜라이더보다 시각상 과도하게 깊게 늘리지 않는다.
T07은 구멍 없는 철판 덱. 슬롯 이름이 timberPlatform이어도 외형 재질은 철재로 사용 가능.
T08은 일반 groundCore/groundCoreVariants에 넣지 않는다.
T08을 기본 사각 블록에 씌우면 기존 안전 BoxCollider가 용암 위를 덮으므로, 별도 구조물/장식 배치와 위험 트리거가 필요하다.
T08은2x2x4 외곽, 테두리 각0.2m 제안. 내부 용암 수면은 약1.6x3.6m, 상면은 로컬UnityY=-0.3m.
-0.3m는 수면 높이이고 메시 두께가 아니다. 용암 메시 두께0.05m 정도의 얇은 슬래브를 제안.
열기/대미지/즉사 여부는 게임 설계 단계에서 결정. 원화의 'hazard' 표기는 구현 완료 의미가 아니다.

6. 원경3D
B01~06은 후면/측면/하부가 있는 실제 입체 모델. 산과 요새를 이미지 평면으로 대체하지 않는다.
B01 분화구는 그릇형 내벽을 만들고 바닥까지 폐쇄. 용암띠3개는 암반과 분리. 연기/화산재는 별도 파티클.
B02/B03은 뒷면까지 단순 큰 면. B04는 실제 관통 구멍과 두꺼운 옆면.
B05는 A01 요새의 단순화 파생형. 중앙동/탑4/뒤쪽 성벽을 유지하고 세부 창·리벳은 생략.
B06 암반과 용암흐름 메시를 분리. 흐름은 바위 표면을 따라 구부린 얇은 볼륨/리본이며 카메라를 향하는 배경 빌보드가 아니다.
용암 흐름 UV를 진행 방향으로 정렬해 스크롤 셰이더 적용 가능하게 한다.
권장 배치 시작값 UnityZ: 작은 프랍+6~12m, 중경+15~30m, 원경+40~100m. 실제 카메라 클리핑/가림 확인 후 조정.
먼 지형은 대비와 발광 강도를 낮춘다. 앞쪽 적과 바닥 윤곽이 가장 명확해야 한다.

7. 프랍·요새
P01은 크기가 다른 결정 기본3종을 조합한다. 메인 군락과 부품 그림의 개수 차이는 조합 변형으로 해석하며 원본3메시를 재사용.
P02는 비발광 바위3개. P03은6각 현무암 기둥5개. P04는 녹슨 붉은색 관목이며 불꽃처럼 움직이지 않는다.
P05 화로의 불꽃은 별도 삽입 메시. 받침4개, 재질 밝기와 실시간 광원은 별개.
P06 등불 고리 위치에 피벗. P09 체인은 단순 저폴리 고리를 반복하며 매 링크 물리 시뮬레이션은 요구하지 않는다.
P10 천은 상단 고정축, P11 파손조각은 분리. P12 분출구의 그레이팅3개 막대는 테두리와 별도.
A01 중앙동 + 모서리탑4 + 성벽모듈 + 문 아치 + 청동뿔2 + 깃발. 거대한 단일 메시로 합치지 않는다.
A02 지붕/기둥/굴뚝/화덕/바닥 분리. 화덕 불빛이 플레이 경로를 가리지 않게 한다.
공유 재질 제안: 현무암/철/청동/붉은천/재/용암/황금수정/목재8개 내외.
발광 무늬는 별도 재질/마스크로 분리. 미세한 균열을 전부 메시로 조각하지 않는다.

8. 기믹
G01 기둥형3m 비콘. 기존 체크포인트 깃발과 시트 장식이 중복되지 않게 연결 단계에서 확인.
G02 유효 통로1.5x3m, 외곽2.7x4x1.2m. v2의 안쪽 CLEAR OPENING 값을 기준으로 한다. 여전히 남은 바깥쪽3m 화살표는 외곽 치수로 사용하지 않는다.
G03 Base/Plate/Emblem 분리. ID는 G03이며 초안A03은 폐기.
G04 gateVisual은 움직이는 격자문만. 고정 가이드와 아치캡은 별도 장식. 실제 판정은 기존 문 BoxCollider를 사용하므로 철창 사이를 통과할 수 있다고 해석하지 않는다.
G05 기준 폭3m(X)/높이0.4m(Y)/깊이4m(Z). v2 FRONT3m / SIDE4m 및 CSV 기준.
v2 큰3/4그림의3m/4m 화살표 방향은 작은 투영도와 시점상 혼동될 수 있으므로 그림 픽셀 비율로 축을 추정하지 않는다.
현재 빌더는 이동 발판 판정 두께0.5m에 맞춰 아트 높이를 확대할 수 있다. 움직이는 메시는 Static 금지.
G06 Spike_01/02/03 세 파츠, 로컬UnityY +0.58m 상승. 경고 상태는 가시가 완전히 내려간 채 슬롯만 발광한다.
실제 공격/접촉 판정은 기존 기능 계약을 검토해 연결하며 원화만으로 새 기능을 구현했다고 처리하지 않는다.

9. 몬스터8종
M01 슬라임: 몸/암석껍질/불꽃돌기/눈 분리. 사지 없음. 스케일 또는2~3본으로 점프.
M02 풍뎅이: 다리6(좌3/우3), 더듬이2, 뿔1. 최종v2에서 정면/후면6개, 측면 가까운3개가 보이도록 교정.
M03 박쥐: 날개2, 발2, 귀2. 별도의 앞팔을 추가하지 않는다. 날개막 두께/양면 재질 검토.
M04 도롱뇽: 다리4, 꼬리1, 등판. 중립 자세에서 네 다리가 실제로 있어야 하며 가려진 다리를 생략하지 않는다.
M05 아르마딜로: 다리4, 꼬리1. 분절 껍질과 몸 분리; RollPivot은 몸 중심, 배치 Root는 바닥 중심.
M06 불씨 정령: 코어1, 공전 암편3, 사지 없음. 암편별 독립 궤도 피벗, 공격파동은 별도FX.
M07 골렘: 팔2/다리2, 육각 가슴코어, 손은 돌 장갑. 팔꿈치·무릎 관절 사이 여유.
M08 수호병: 팔2/다리2, 철퇴/방패/망토 별도; 무기 장착점과 망토 상단 피벗.
제안 동작: Idle/Move/Attack/Hit/Death. 비행체Fly, 구체Roll, 슬라임Jump 등 개별 동작 추가.
붉은색 전체 도색 대신 어두운 외곽+작은 발광 코어로 실루엣을 유지한다.
돌진/비행/불숨결/구르기/파동 AI와 데미지·밟기 판정은 별도 구현. Mxx를 MonsterTable 숫자ID로 임의 등록하지 않는다.

10. 이펙트
08은 타임라인 원화이며 정렬된 알파 아틀라스나 완성 파티클 프리팹이 아니다.
Blender 제작 부품: 암편3형, 재 덩어리, 용암방울3형, 스플래시 크라운, 얇은 링, 불꽃3상, 냉각 조각, 기포돔, 흐름 메시.
환경 용암면은 기본4x4m 또는8x8m 반복 타일로 만들고 UV/셰이더 흐름을 맞춘다. 원경의 입체 조건과 액체 표면·입자에 리본/쿼드 메시를 쓰는 것은 별개다.
FX03의 기포는 웅덩이 안에서만; 주변 안전 바닥으로 튀어나와 보이지 않게 한다.
FX04는 P12 분출구 + 경고링 + 화염. 예고0.7초/분출0.8초/잔광0.4초를 시작값으로 제안하되 게임 난이도로 조정.
FX04는 새로운 위험 제어가 필요하다. spikeTrapVisual 슬롯에 불꽃을 넣는 것만으로 정확한 화염 판정이 생기지 않는다.
FX05 방울은 시각용/위험 투사체 중 역할을 별도 결정. 장식 방울을 대미지 투사체로 오해하게 보이지 않게 한다.
FX06은 G01에 링/빛점을 추가. FX07의 단순 문판은 연출 설명용이며 실제 모델은 G04 격자문을 재사용.
FX08은 작은 숯 퍼프와암편/불티. 화면을 덮는 큰 폭발·짙은 연기를 피한다.
모든 수명/치수/삼각형 예산은 CSV 참고. 실제 파티클 및 셰이더·이벤트 연결은 후속 작업.

11. 검수 및 납품
우선순위: 이 명세와 CSV → 개별 시트 → 전체 컨셉샷.
원화 투영도는 정밀 CAD가 아니므로 숫자 치수로 블록아웃하고 모든 방향에서 확인.
검수 순서: T01~04 반복 접합/원점 → T05~08 → P군/A군/G군 → B군 → M군 → FX.
