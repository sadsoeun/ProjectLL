CORAL COAST — 월드 4 산호 해안 / Blender 모델링 제작 명세
작성: 2026-11-13
산출물: 최종 원화 PNG 8장, 제작 명세, 에셋 CSV, 생성 프롬프트, Claude 인계문
설계 항목: 지형8 + 원경6 + 몬스터8 + 프랍12 + 건축2 + 기믹6 + 이펙트8 = 50
상태: 원화/설계 단계. 실제 .blend / FBX / 리깅 / Unity 프리팹은 아직 제작하지 않음.

1. 기준과 범위
사용자가 업로드한 FIVE REALMS 월드맵의 4번 CORAL COAST 지역을 기준으로 한다.
모래를 얹은 석회암 섬, 야자수, 산호, 얕은 청록 바다, 부두, 난파선, 소라 지붕의 궁전을 연결한다.
근경은 따뜻한 모래/산호색, 원경은 대비를 줄인 청록/아이보리로 구성한다.
플레이는 수면 위 발판에서 진행하는 2.5D 플랫포머를 가정한다.
수영/잠수/실제 부력/조석 변동은 이 원화 작업에 포함되지 않는다.
현재 Data/StageLayouts에서 W4*.json은 발견되지 않았다. 컨셉샷은 실제 점프 거리 검증이나 확정 레벨 좌표가 아니다.
이 패키지는 이전 3스테이지와 같은 제작 형식으로 새로 만든 월드 4 키트다. 기존 원화/게임 파일을 교체하지 않는다.

2. 확인한 맵툴 계약
- 플레이 평면은 Unity X/Y, 깊이는 Z. 기본 지형 깊이 4m.
- 블록 x/y는 좌상단, y가 표면이며 몸체는 아래로 내려간다.
- 기본 지형: 2x2x4m, 공중 발판: 3x1x4m, 얇은 목재: 3x0.4x4m.
- 테마 아트를 기본 콜라이더 오브젝트 아래 붙이고 원래 렌더러만 숨긴다. 아트 콜라이더는 비활성화된다.
- groundCore/groundEndLeft/groundEndRight/rockCore와 변형 배열, floatingPlatform/timberPlatform 슬롯이 있다.
- checkpointVisual/goalVisual 및 moverVisual/switchVisual/gateVisual/spikeTrapVisual 등을 지원한다.
- 장식은 prop,x,y,z,rotY,scale. z 미지정 값 -9999일 때만 PropTable defaultZ를 사용한다.
- PropTable에서 Implemented 상태이고 프리팹이 존재해야 장식을 배치한다.
- 0.25/0.5/1m 격자, 저장/검증/씬 빌드 흐름을 지원한다.
- 몬스터는 MonsterTable 숫자 ID를 사용한다. M01~M08은 이 원화의 디자인 ID이며 런타임 등록 번호가 아니다.
- 자동 테마 탐색은 T01_~T04_, T06_, T07_, G01_, G02_, G03a_, G03b_ 접두어를 사용한다.
  본 패키지의 G03~G06은 별도 제작 ID이므로 기믹 슬롯에 수동으로 올바르게 연결한다.

4. 단위·축·피벗
1 Blender unit = 1m. CSV W/H/D는 Unity X/Y/Z 기준.
Blender는 X=폭, Z=높이, Y=깊이로 제작하고 FBX 축 변환 후 Unity X 진행/Y 위/Z 깊이를 기준 큐브로 검증.
변환을 이중 적용하지 않는다. 모델별 임의 90도 회전 대신 프로젝트용 내보내기 설정을 통일한다.
top-left 피벗: Blender x=0,z=0,y=0; 모델 범위 x 0..W / z -H..0 / y -D/2..D/2.
bottom-center 피벗: 바닥 z=0, X/Y 중심 0.
body-center는 비행체의 중심. 별도 배치용 Root가 필요하면 바닥 기준 Root 아래 중심 피벗을 둔다.
emitter는 효과 발생점이며 데이터에 고정된 공통 크기가 있는 메시가 아니다.
최종 루트 스케일 1. 회전/스케일 적용 후 자식의 회전축·애니메이션 원점을 보존한다.
CSV 치수 중 기존 지형 규격 외 값은 제안치이며 카메라/캐릭터 크기로 최종 조정한다.
삼각형 예산은 최종 triangles 기준. LOD1 약50%, LOD2 약25%에서 실루엣을 보며 줄인다.

5. 바닥 상세
T01: 모래 캡 + 석회암 코어 합계 2m 높이. 캡 제안 두께0.15m, 코어1.85m.
02 시트의 작은 분해도에 캡/코어 각각 2x2x4로 표시된 것은 부정확하다. 합쳐진 전체만 2x2x4m다.
T02 왼쪽은 외부, 오른쪽은 접합. T03은 반대. T01/T04/T05 경계 프로파일을 일치시킨다.
T04에는 모래 캡이 없다. 높게 적층할 때 매 단마다 모래 띠가 나오지 않게 한다.
T05 포장 상면을 기준 높이0에 맞춰 내린다. 시트처럼 보도석이 튀어나와 콜라이더 표면보다 높아지지 않게 전체 높이를2m 안에 유지.
T06 하부 바위는 원형 3x1x4m 안에 들어가게 한다.
T07의0.4m는 덱 두께만. 난간은 P10/P11 등을 재사용하여 별도 배치.
T08은 밑바닥 중심 피벗의 장식 지지대다. 빌더 지형 슬롯이나 이동 발판의 일부로 자동 사용하지 않는다.
플레이 평면을 수평으로 유지한다. 모래/바위의 가장자리는 옆/아래로만 부드럽게 깎는다.

6. 실제 3D 원경
B01~B05는 후면/측면/밑면까지 있는 입체 메시다. 사진·일러스트를 붙인 빌보드로 대체하지 않는다.
B03의 바위 아치는 관통 구멍과 두꺼운 측면을 갖는다.
B06 난파선은 원래 열린 선체이므로 입구를 막지 않는다. 대신 선판/늑골에 두께를 주고 내외부 면과 법선을 정상으로 만든다.
배치용 B06 Root는 바닥 중심, 선체 Hull은 중립 자세로 제작 후 부모 TiltRoot에서 기울인다.
B05는 A01 궁전의 단순화형. 뒤쪽 성벽과 탑을 생략하지 말고 미세 장식을 줄인다.
권장 Unity Z 시작값: 작은 프랍+6~12m, 중경+15~30m, 원경+40~100m. 확정 카메라 값이 아니며 가림/안개/클리핑을 확인한다.
원경 대비와 채도를 줄이고 가장 먼 섬의 실루엣을 단순화한다.
바다는 별도 WaterSurface 메시 타일(예:32x32m, 단순 세분)과 포말 스트립으로 제작한다. FX03 제작 부품에 포함하며 반사/굴절/수위는 게임 셰이더에서 구현한다.
환경 원경이 입체라는 조건과 수면·파티클에 평면/리본 메시를 사용하는 것은 별개다.

7. 프랍과 건축
P01 줄기/잎/열매 분리. 잎은6개를 기준으로 굵고 단순한 면, 피벗은 줄기 접합부.
P03 주 가지3개를 기준으로 단순화. 산호에 미세 돌기를 과도하게 추가하지 않는다.
P05는 가리비/소라/대합3개 개별 모델. 열린 껍데기 안쪽과 가장자리 두께를 표현한다.
P06/P07은 장식 모델이며 파괴 기능은 별도. 나무통 뚜껑/금속테를 분리한다.
P09 등불 고리, P11 천 상단을 회전 피벗으로 한다. 실제 광원은 메시와 별도.
P10 단일 기둥과 로프 구간을 분리하여 반복 조합. 로프는 낮은 단면 분할수 사용.
A01 중앙동/큰 소라 지붕/모서리 탑4/성벽/아치 모듈. 인접한 장식은 P군을 재사용한다.
A02 정자는 장식으로 사용하면 콜라이더를 끄고, 실제 플레이 바닥은 기존 블록으로 따로 구성한다.
따뜻한 석회암, 모래, 목재, 산호, 잎, 금속, 천, 진주 등 공유 재질8개 내외 권장.
진주는 불투명 밝은 재질에 하이라이트/약한 발광으로 우선 제작. 모든 조개에 실제 굴절을 적용하지 않는다.

8. 기믹 파츠와 코드 연결
G01은 3m 높이 기둥형 진주 비콘을 모델링 기준으로 한다. 컨셉샷의 낮은 조개 받침은 분위기 표현용이며 별도 두 번째 체크포인트를 만들지 않는다.
기존 checkpoint의 깃발 시각 요소가 남으므로 원화의 파란 깃발을 중복 표시하지 않도록 연결 단계에서 조정.
G02의1.5x3m는 유효 통과 공간. 시트의3m 치수선은 외곽까지 걸쳐 보이나 내부 공간 기준으로 해석한다. 외곽은 CSV 2.7x4x1.2m.
G03 Base/Plate/Emblem을 분리한다. 시트에서 무늬가 판과 붙어 보여도 런타임 탐색을 위해 Emblem 자식을 따로 둔다.
G04 gateVisual은 이동하는 문 판만. 좌우 가이드는 고정 장식으로 따로 두어 문과 같이 들리지 않게 한다.
G05는3x0.4x4m 원형이며 현재 빌더의 이동 발판 충돌 두께0.5m로 시각 높이가 확대될 수 있다.
뗏목의 떠 있는 모습은 아트 설정이며 부력 시뮬레이션을 의미하지 않는다. 이동 메시는 Static 금지, 지지대 T08을 붙이지 않는다.
G06 가시3개는 Spike_01~03. 로컬 Unity Y 방향+0.58m 상승, 경고 중에는 완전히 내려간 상태에서 슬롯만 빛난다.
기믹의 기존 판정 영역을 원화에 맞춰 무단 변경하지 않는다.

9. 몬스터8종 — 모델링과 동작 제안
M01 해안 게: 보행 다리8(좌4/우4), 집게2, 눈자루2. v2에서 정면/후면/파츠도를 교정했다. 사족이나 육족으로 단순화하지 않는다. 동작 Idle/SideWalk/Claw/Hit/Death.
M02 소라게: 밖으로 보이는 보행 다리4(좌2/우2), 집게2. 숨은 후방 소형 다리는 껍데기 내부로 처리. 몸을 껍데기 안으로 수축하는 피벗 분리.
M03 복어: 옆 지느러미2, 등1, 꼬리1. 몸통 팽창은 약1.2배부터 제안, 가시는 굵은 낮은 원뿔. 원화의 큰 팽창 모습은 연출용이며 게임 충돌 크기는 별도 결정.
M04 해파리: 갓1, 촉수4, 눈2. 촉수 각각2~3개 본. 불투명 민트 기본안과 투명 셰이더 옵션을 분리.
M05 불가사리: 팔5개. Root 아래에 중심 SpinPivot을 두고 회전. 시트의 팔5개 형상을 유지.
M06 갈매기: 날개2, 물갈퀴 발2, 부리1. 날개 펼친 범위와 다이빙 자세 간섭 검사.
M07 거북: 걷는 다리4, 목1, 꼬리1. 물갈퀴형으로 바꾸지 않는다. 등껍질과 몸/목 분리.
M08 수호자: 팔2/다리2/진주 코어. 손은 돌 장갑형, 어깨 산호는 관절과 간섭하지 않게 분리.
복어·해파리는 수면 위에서 부유하는 판타지 적을 제안한다. 현재 비행/부유/잠수 AI가 준비되었다고 가정하지 않는다.
모든 AI/피격/밟기 판정/이동 경로/숫자ID 등록은 별도 게임 구현 작업이다. 원화만으로 Implemented 처리하지 않는다.
캐릭터 일반 폴리곤 예산은 CSV 참고. 짧은 발/집게는 애니메이션에 필요한 관절 루프만 둔다.

10. 이펙트 제작
08은 연출 타임라인 원화이며 즉시 잘라 사용하는 알파 스프라이트 아틀라스가 아니다.
Blender: 모래 알갱이3형, 물방울3형, 산호 파편3형, 링, 포말 리본, 스플래시 크라운, 저폴리 거품 구체, WaterSurface.
Unity: 파티클 수명/크기/알파, 필요한 소프트파티클, 수면 스크롤, 사건별 재생 연결.
FX01/02/05/08은 작은 범위로 제한. 지면에서 생기는 FX02는 얕은 물 표면 장식이며 수영 기능이 아니다.
FX03은2~4초 포말 반복. START와FADE를 자연스럽게 연결하고, 바위 메시를 움직이지 않는다.
FX04는 해파리 공격의 시각 제안. 링 반경이 곧 데미지 영역이라는 가정을 하지 않는다.
FX06 비콘 모양은 효과 설명용 간소화다. 실제 하드웨어 모델은07 G01을 사용하고 링/빛점만 추가한다.
FX07 그림의 파도 무늬와07 G04의 조개 엠블럼은 서로 다른 역할: 문 고정 장식은 조개, 활성 시 일시적으로 표시하는 오버레이가 파도 룬.
실제 투명 PNG/메시/파티클 프리팹은 후속 제작 대상이다.

11. 원화 해석과 검수
원화의 투영도는 정밀 CAD 도면이 아니다. 이 명세와 CSV 수치 → 개별 원화 시트 → 컨셉샷 순서로 우선.
T01 분해도 캡 치수, T05 표면 높이, G02 통로 치수, G01/FX06 비콘 차이는 위 설명대로 통일한다.
B06의 FRONT는 선체 측면 실루엣이 잘 보이는 방향이다. Blender 로컬 정면은 별도로 정하고 에셋 내에서 일관되게 유지한다.
팔·다리가 겹쳐 덜 보이는 뷰에서는 중립 정면과 분리 파츠도를 함께 읽는다. 최종 개수는9항 기준.
캐릭터/프랍은 재질 경계와 실제 메시 분리 경계를 혼동하지 않는다.

12. 추천 제작 순서와 납품
T01~T04 치수/반복 접합 테스트 → 나머지 지형 → P군 → A/G군 → B군 → M군 → FX 부품.
첫 모델은 Unity로 불러와4m 깊이/상면0/스케일1/정면 방향을 검사한 뒤 확장한다.
각 모델은 정면·측면·후면·아래쪽 검수, 비매니폴드/겹친면/뒤집힌 법선, 움직이는 자식 피벗, LOD 실루엣을 확인.
납품: 편집용 .blend, 개별 FBX, 공유 재질과 텍스처, 리깅 파일, 치수/삼각형 수 목록, 회전 검수 이미지.
현재 패키지는 위 제작을 위한 원화/설계 인계이며 모델 제작이나 실제 게임 적용 완료를 의미하지 않는다.
