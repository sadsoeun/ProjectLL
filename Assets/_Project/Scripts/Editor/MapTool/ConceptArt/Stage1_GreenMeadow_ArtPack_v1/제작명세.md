일러스트는 120m 코스를 한 화면에 압축한 분위기 표현이다. 그림에서 보이는 발판 수·높이·틈 너비를 레벨 데이터로 옮기지 않는다. 실제 레이아웃 수치는 아래 표와 원본 JSON을 따른다. 다면도는 형태를 설명하는 원화이며 CAD 도면이 아니다. 뷰 간 세부 차이는 정면 실루엣과 이 문서의 수치를 우선해 블록아웃에서 통일한다. 시트의 와이어프레임은 형태 분할 제안이며 실제 메시의 토폴로지 검증 결과가 아니다.

## 1. 분석한 소스와 확인된 기능

프로젝트 내 다음 소스를 직접 확인했다. 이번 작업은 원화 제작이며 C#·JSON·씬·프리팹을 변경하지 않았다.

- `Assets/_Project/Scripts/Editor/MapTool/StageMapToolWindow.Panels.cs`: 팔레트, 파일 열기·저장, 격자 0.25 / 0.5 / 1m, 스냅과 표면 스냅.
- `StageMapSession.cs`, `StageLayoutEditOps.cs`, `LayoutGeometry.cs`: 기본 격자 0.5m, X/Y 평면 배치, 이동·크기 조절·복제, 표면 조회와 오브젝트 표시 범위.
- `Assets/_Project/Scripts/Editor/StageLayoutData.cs`: 블록·체크포인트·코인·특수 수집물·가시·이동 발판·적·낙하물·시작·목표·구간 데이터.
- `StageLayoutBuilder.cs`, `StageLayoutBuilder.Prefabs.cs`: 깊이 4m의 블록, 실제 콜라이더·트리거, 기본 프리미티브 생성과 씬/프리팹 재생성.
- `SceneFlowSetup.Scenes.cs`: 게임플레이 카메라 생성값 위치 (0,3,-16), X 회전 3도, FOV 50도, 추적 오프셋 (0,2,-16). 실제 실행 씬의 시각 검증은 이번 범위에 포함하지 않았다.
- `Assets/_Project/Data/StageLayouts/W1_S1.json`: 실제 1-1 배치의 기준.

맵툴은 3D 오브젝트를 사용하는 X/Y 횡스크롤 스테이지 편집기다. 첨부된 월드맵의 등각 구도를 플레이 카메라로 그대로 사용하지 않고, 초원 지역의 색·형태·랜드마크를 횡스크롤 배경으로 전환했다.

현재 JSON에는 장식 프리팹 경로, 배경 레이어, Z 위치, 재질/바이옴 선택 필드가 없다. 임의의 나무나 풍차를 현재 팔레트에서 배치할 수 있다고 가정하지 않는다. 빌더는 블록을 Cube로 만들고 공유 기믹 프리팹과 씬을 다시 생성한다. 따라서 향후 적용 시 아트 메시 생성 연결 또는 별도 장식 프리팹/씬 유지 경로가 필요하다. 생성된 씬에 수동으로 장식한 것만으로는 재빌드 후 보존되지 않는다.

## 5. 피벗·충돌·블렌더 제작 기준

1. 제작 단위는 1m로 통일한다. Blender의 위쪽 축과 Unity Y-up 변환을 고려해, 시험용 1m 큐브와 방향 표식 하나를 먼저 내보내 실제 임포트 크기·방향을 확인한다. 특정 exporter 설정이 이미 구성돼 있다고 가정하지 않는다.
2. 원화의 FRONT는 카메라가 음수 Z에서 양수 Z 방향으로 보는 면이다. LEFT/RIGHT 접속면과 실제 게임 X 방향을 고정한다. 트랜스폼을 적용한 뒤 본체 scale 1을 기준으로 관리한다.
3. 아트 블록 모듈의 조립 원점은 좌상단/깊이 중앙을 제안한다. 그러나 기존 빌더의 Cube 원점은 중심이다. 실제 중심은 `(x+w/2, y-h/2, 0)`. 아트 자식을 연결할 때 오프셋을 변환해야 하며 모듈 원점을 기존 루트 원점과 혼동하지 않는다.
4. 장식물은 바닥 중심, 코인·보석은 중심, 풍차 날개는 회전축 중심을 피벗으로 둔다. 날개를 본체와 분리한다. 풍차 평면도에서는 수직 회전면의 날개가 얇게 보이는 것이 맞다.
5. 블록의 기존 BoxCollider와 상단 높이를 유지한다. 잔디 테두리가 시각적으로 틈을 메우지 않게 한다. 부드러운 잔디 장식은 발판 폭 밖으로 과하게 돌출시키지 않는다. 가는 목재 발판의 지지대에는 충돌을 추가하지 않는다.
6. 정면 실루엣과 큰 면 분할부터 만든다. 나무는 개별 잎 대신 수관 덩어리, 바위는 큰 각면, 지붕은 큰 판재를 사용한다. 작은 홈·벽돌 줄눈은 컬러/노멀 표현으로 대체 가능하다.
7. 원경 LOD는 수관 덩어리 수, 바위 면 수, 지붕 조각을 줄여 만든다. LOD1은 원본의 약 50%, LOD2는 약 20–30%를 시작점으로 제안한다. 실제 전환 거리는 게임 화면에서 확인한다.

## 6. 원경을 실제 3D로 제작하는 방식

원경은 입체 언덕, 합쳐진 숲 수관, 다면체 바위 기둥, 단순 메시 구름으로 제작한다. 나무/언덕을 카메라에 붙인 평면 그림으로 대체하지 않는 방향이다. 수면은 넓은 평면 메시가 적합하며, 폭포 물띠는 별도 메시와 포말 메시로 분리한다. 물결의 잔무늬까지 전부 기하로 만들 필요는 없다.

| 레이어 | Unity Z 제안 | 원칙 |
|---|---:|---|
| 플레이 충돌 영역 | 중심 0, 지형 범위 -2…+2 | 이동·착지·판정 기준 |
| 가까운 배경 | +6…+12 | 큰 나무, 풍차, 울타리, 폭포 절벽; 메시 앞끝도 플레이 영역 뒤 |
| 중경 | +20…+40 | 넓은 구릉·숲 덩어리, 대비를 낮춤 |
| 원경 | +50…+100 | 먼 암초·언덕·구름, 푸른색으로 통일 |

이 깊이는 새 아트 배치 제안이며 맵툴에 저장된 값이 아니다. 카메라는 생성 코드상 z=-16이다. 원근 카메라에서는 뒤쪽 모델이 작아지므로 레이어 거리만 옮기지 말고 화면상 실루엣 크기를 확인해 모델 스케일을 맞춘다. 자연스러운 시차는 거리 차로 얻을 수 있지만 전용 패럴랙스/배경 스트리밍 기능이 구현돼 있다는 의미는 아니다.

폭포·수면은 장식이며 이 스테이지의 수영/수면 충돌 기능을 새로 가정하지 않는다. 실제 사망 기준 killY=-8을 유지하고, 물이 안전한 착지면처럼 보이지 않도록 낙하 구간보다 충분히 아래/뒤로 배치한다.

## 7. 모델링 진행 순서와 확인

먼저 T01·T04·T06·T07로 기존 레이아웃과 같은 블록아웃을 만든다. 다음 V01과 A01로 형태 기준을 잡고, 장식 프랍·G01/G02를 제작한다. 마지막에 B01–B06을 배치하고 멀어질수록 대비와 면 수를 줄인다.

최종 게임 적용 단계에서는 (a) 4개 D 발판과 3개 E 발판의 크기/틈, (b) 시작과 체크포인트의 시야, (c) 골인 아치의 통과 공간, (d) 수집물 색 구분, (e) 재빌드 후 아트 유지 방식을 확인한다. 이번 납품은 PNG 원화와 제작 명세이며 `.blend` 모델, Unity 적용 또는 성능 검증을 완료한 결과물은 아니다.

생성 방식: 내장 image_gen. 첨부 월드맵은 초원 무드 참고로 사용했고, 후속 시트는 01 컨셉샷을 공통 디자인 참조로 사용했다. 검수 후 절벽 적층 코어, 풍차 평면도, 판정 치수 표기, 원경 구릉/깊이 설명도를 수정했다.
