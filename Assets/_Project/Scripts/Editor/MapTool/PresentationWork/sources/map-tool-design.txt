1. 요약
1.1 한 장 요약
무엇: Tools/MyGame/Map Tool/Open Map Tool  메뉴로 여는 에디터 전용 창(StageMapToolWindow ). 스테이지 레이아
웃 JSON을 열고, Scene 뷰의 X/Y 평면에서 모든 요소(블록·체크포인트·코인·특수 수집품·가시·이동 발판·적·낙하물·시
작점·목표점·구간)를 격자 스냅으로 배치·이동·크기 조절·삭제하고, 속성을 편집하고, 저장합니다.
단일 진실 원천: 편집 대상은 메모리의 StageLayoutData  하나이며 파일은 JSON뿐입니다. 편집 중에는 씬에
GameObject를 만들지 않습니다(Handles 오버레이). 씬은 지금처럼 빌더가 JSON에서 생성합니다.
재사용: 데이터 클래스(StageLayoutData.cs ), 검증기(StageLayoutValidator.Validate ), 빌더(StageLayoutBuilder.
BuildFromFile ), 몬스터 테이블(MonsterTableTool.Load )을 수정 없이 호출합니다. 기존 파일 수정은 색상 표 Palet
te 의 접근 한정자 1곳(private  → internal )뿐입니다.
계약 영향 없음: JSON version  1, 스키마 v1.2 그대로. 저장 형식은 기존 파일과 같은 들여쓰기 1칸 정규 형식(실측
으로 확인)으로 기록해 diff를 최소화합니다.
Undo: 모델을 HideFlags.DontSave  ScriptableObject(StageLayoutDocument )에 담아 Unity Undo(Undo.RecordObjec
t )를 그대로 사용합니다. 드래그 한 번 = Undo 한 단계.
빌드 + 플레이: 저장 → 검증 → BuildFromFile  → 06_InGame  + Stage_<id>  씬을 함께 연 상태에서 InGameContro
ller.debugStageId 를 메모리에서만 바꿔 Play → 종료 시 원래 씬 구성을 복원. 런타임 코드는 바꾸지 않습니다.
AI 레벨디자이너 지원: GUI를 쓸 수 없는 에이전트(Coplay MCP로 에디터 코드 실행)를 위해 StageMapAutomation
정적 API(검증·정규화 저장·빌드·플레이 테스트)를 제공합니다.
1.2 핵심 결정 (자세한 근거는 5장)
ID 결정 대안과 기각 이유(요약)
D-01 편집은 Scene 뷰 Handles 오버레이(GameObject 없
음). 어느 씬이 열려 있어도 동작.
전용 미리보기 씬의 GameObject 편집: 씬 ↔ JSON 양방향 동기
화, 빌더의 씬 전환(Single 모드)·더티 씬 자동 저장과 충돌, 진실
원천이 둘이 됨.
D-02 UI는 IMGUI EditorWindow. UI Toolkit: Scene 뷰 Handles는 어차피 IMGUI이고, 프로젝트에
UI Toolkit 에디터 코드가 없어 학습·일관성 비용 증가.
D-03 정규 JSON 작성기(StageLayoutJson.Write ) 자체 구
현. 읽기는 기존과 같은 JsonUtility.FromJson .
JsonUtility.ToJson : 4칸 들여쓰기, 선택 필드(section ·mon
sterId ·speed )도 모두 기록 → 기존 파일 전체가 바뀌는 큰
diff.
D-04 더티 = 현재 정규 JSON ≠ 마지막 저장 정규 JSON (문
자열 비교). 저장 스냅숏은 Undo 대상 밖(창 상태)에 둠.
변경 카운터: Undo로 원상태가 되어도 더티로 남음.
D-05 플레이 테스트는 씬 구성 저장 → 빌드 →
InGame+Stage 동시 열기 → debugStageId 메모리
변경 → Play → 복원.
런타임 훅 추가: 런타임 코드 변경 필요. sceneNameOverride
로 등록 씬 덮어쓰기: 다른 스테이지 씬을 파괴.
D-06 검증은 기존 검증기를 그대로 호출하고, 메시지 문자열
에서 요소 ID를 찾아 선택 연결(편의 기능).
검증기에 구조화된 위치 정보 추가: 계약 측 코드 수정과 회귀
위험. 이번 범위에서는 불필요.

5.7 기타 결정
D-07 좌표 정밀도: 편집으로 만들어지는 모든 실수 값은 스냅 값 또는 0.01 m로 반올림. 작성기는 소수 4자리까지
기록.
D-08 Assertion: 내부 불변식은 기존 런타임 코드와 같은 UnityEngine.Assertions.Assert 를 사용(에디터에서 활
성). 파일·사용자 입력·테이블은 Assertion이 아닌 명시적 검사와 메시지로 처리.
D-09 ID 안정성: 요소를 다른 구간으로 옮겨도 ID는 자동으로 바꾸지 않음(체크포인트 ID 등 참조 안정성). 필요 시
속성 패널에서 변경.
D-10 UI 문구: 버튼·메시지는 한국어, 필드 라벨은 계약 키 이름(x , w , range  …) 그대로 표시해 스키마 문서와 1:1
대응.
