1. 개요
1.1 문서 목적과 범위
이 문서는 게임 실행부터 인게임 플레이까지 거치는 6개 씬의 구조와 이동 순서(씬 플로우)를 정의합니다. 각 씬이 맡는
역할, 씬 안에 배치할 오브젝트, 다음 씬으로 넘어가는 조건, 씬 사이에서 유지해야 하는 데이터를 다룹니다.
포함: 씬 목록, 씬 플로우, 씬별 구성과 동작, 공통 시스템, 데이터 구조, 예외 처리
제외: 플레이어 조작 수치, 레벨 디자인, 아트·사운드 세부 사양 (별도 문서로 다룸)
1.2 설계 원칙
원칙 내용
씬마다 하나의 책
임
씬은 한 가지 목적만 가집니다. 설정처럼 여러 곳에서 쓰는 UI는 씬이 아니라 팝업 프리팹으로 만들어 재
사용합니다.
전환은 한 곳에서 모든 씬 이동은 SceneLoader 를 통해서만 요청합니다. 각 씬이 SceneManager 를 직접 호출하지 않습니
다.
상주 시스템 분리 설정, 세이브, 언어, 오디오, 화면 페이드처럼 게임 전체에 걸친 기능은 씬에 두지 않고 상주 오브젝트
( GameSystems )로 관리합니다.
어느 씬에서든 실
행 가능
에디터에서 어떤 씬을 바로 실행해도 상주 시스템이 자동 생성되도록 합니다. 작업 중인 씬을 열 때마다
로고부터 시작할 필요가 없어야 합니다.
데이터와 씬 분리 스테이지 정보, 월드맵 노드 정보는 ScriptableObject 데이터로 관리하고, 씬은 그 데이터를 읽어서 동작합
니다.
1.3 현재 프로젝트 상태 (2026-10-29 확인)
항목 상태 이 문서에서의 처리
씬 템플릿 기본 SampleScene  1개만 존재 6개 씬을 새로 만들고 Build Profiles의 씬 목록에 등록

인게임에서만
스테이지 맵을 별도 씬으로 두는 이유
인게임 씬은 플레이어, 카메라, HUD처럼 모든 스테이지에 공통인 요소만 가진 "틀"입니다. 스테이지 지형은 스테이지마다
씬 하나로 만들어 인게임 씬 위에 추가로 불러옵니다. 이렇게 하면 레벨을 에디터에서 일반 씬처럼 편집할 수 있고, 조명 베
이크도 스테이지별로 관리할 수 있으며, 공통 요소를 스테이지마다 복사하지 않아도 됩니다.
2.2 네이밍 규칙
메인 씬은 두  자리  번호 _PascalCase  형식입니다. 번호가 곧 플로우 순서이므로 Project 창에서도 순서대로 정렬됩니
다.
스테이지 씬은 Stage_W{ 월드 }_S{ 스테이지 }  형식입니다. 예: Stage_W1_S1 , Stage_W2_S3
코드에서는 씬 이름 문자열을 직접 쓰지 않고 SceneId  열거형(enum)과 매핑 테이블을 통해 참조합니다. 파일명을
바꿔도 한 곳만 고치면 됩니다.
2.3 씬 간 이동 방식 요약
방식 사용 구간 이유
페이드 전환 로고 → 언어 선택 → 타이틀, 월드맵 → 타
이틀
가벼운 UI 씬이라 로딩 화면 없이 페이드만으로 충분합니다.
로딩 경유 타이틀 → 월드맵, 월드맵 ↔ 인게임 3D 맵, 캐릭터, 스테이지 데이터처럼 로드 시간이 긴 리소스를
다룹니다.
씬 내부 처리 인게임 재시작, 일시정지, 설정 팝업 씬을 다시 불러오지 않고 상태만 초기화해 대기 시간을 줄입니
다.

3.3 공통 전환 규칙
1. 전환이 시작되면 입력을 잠급니다. 페이드 도중 버튼을 연타해도 전환이 중복 요청되지 않습니다.
2. 이미 전환 중일 때 들어온 요청은 무시합니다.
3. 화면이 완전히 어두워진 뒤 씬을 바꾸고, 새 씬의 초기화가 끝난 뒤 페이드 아웃합니다.
4. BGM은 페이드와 같은 길이로 볼륨을 줄였다 키웁니다. 같은 BGM을 쓰는 씬끼리는 끊지 않고 이어서 재생합니다.
5. 로딩을 거치는 전환에서는 이전 씬을 내린 뒤 사용하지 않는 리소스를 정리( Resources.UnloadUnusedAssets )합니다.

4. 공통 시스템
4.1 상주 시스템 (GameSystems)
씬이 바뀌어도 사라지지 않아야 하는 기능을 하나의 프리팹 GameSystems 로 묶습니다. 이 프리팹은 게임이 시작될 때 한
번 생성되고 DontDestroyOnLoad 로 유지됩니다. 각 기능은 별도 컴포넌트로 나눠 책임을 분리합니다.
컴포넌트 책임 주요 기능
SceneLoader 씬 전환 전환 요청 접수, 페이드 · 로딩 경유 여부 결정, 중복 요청 차단, 로딩 씬에 대상 정보
전달
ScreenFader 화면 페이
드
최상단 Canvas의 검은 이미지 알파 조절, 페이드 중 입력 차단
SettingsService 설정 관리 설정 파일 로드 · 저장, 언어 선택 여부 확인, 볼륨 · 화면 설정 적용
SaveService 세이브 관
리
세이브 존재 · 유효성 확인, 새 세이브 생성, 진행 상황 저장 · 로드
LocalizationService 언어 적용 현재 언어 변경, 언어 변경 이벤트로 화면 텍스트 즉시 갱신
AudioService 사운드 BGM 재생 · 교체 · 페이드, 효과음 재생, Audio Mixer 볼륨 반영
InputModeService 입력 모드 InputSystem_Actions 의 Player  / UI  액션 맵 전환, 전환 중 입력 잠금
4.2 씬 전환 처리 방식
씬에서는 아래처럼 목적지만 전달합니다. 페이드, 로딩, 입력 잠금은 SceneLoader 가 처리합니다.
// 페이드만  사용하는  전환
SceneLoader.Load(SceneId.Title);
// 로딩  씬을  거치는  전환  ( 스테이지  정보  함께  전달 )
SceneLoader.LoadWithLoading(new LoadRequest(SceneId.InGame, stageId: "W1_S1"));
페이드 전환 순서
1. 입력 잠금
2. 화면 페이드 아웃 (검게)
3. 대상 씬 비동기 로드
4. 새 씬 초기화 완료 대기
5. 화면 페이드 인
6. 입력 잠금 해제
로딩 경유 전환 순서
1. 입력 잠금, 페이드 아웃
2. LoadRequest  보관 후 로딩 씬 로드
3. 페이드 인 → 로딩 화면 표시
4. 로딩 씬이 대상 씬과 리소스를 로드
5. 페이드 아웃 → 대상 씬 활성화
6. 페이드 인, 입력 잠금 해제
4.3 에디터에서 개별 씬 바로 실행
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)] 를 사용하는 GameBootstrapper 가
첫 씬이 열리기 전에 GameSystems  프리팹을 생성합니다. 따라서 로고 씬이 아니라 월드맵이나 인게임 씬을 직접 실행해
도 상주 시스템이 정상 동작합니다.

8. 예외 상황 처리
상황 처리
설정 파일이 없거나 깨짐 기본값으로 새로 만들고 "언어 선택 안 함"으로 간주 → 언어 선택 씬 표시
세이브 파일이 깨짐 .bak  파일로 복구 시도. 실패하면 세이브 없음으로 처리하고 이어하기 비활성, 안내
메시지 표시
세이브 버전이 더 낮음 버전별 변환 처리 후 로드
언어 선택 도중 앱 종료 저장 전이므로 다음 실행에서 언어 선택 씬 다시 표시
전환 중 버튼 연타 입력 잠금과 중복 요청 무시로 차단
존재하지 않는 StageId 전달 오류 로그 남기고 월드맵으로 복귀 (에디터에서는 디버그 스테이지 로드)
스테이지 씬이 Build Profiles 목록에
없음
에디터 검증 도구로 미리 확인. 런타임에는 오류 로그 후 월드맵 복귀
일시정지 상태로 씬 이동 씬을 떠날 때 항상 Time.timeScale = 1 로 되돌림
창 포커스 잃음 (PC) 인게임 Playing 상태라면 자동 일시정지
언어 변경 후 이미 열린 화면 언어 변경 이벤트를 받아 표시 중인 텍스트와 폰트 즉시 갱신
다국어 폰트 주의
중국어 · 일본어 · 한국어는 글자 수가 많아 하나의 폰트 에셋에 모두 담기 어렵습니다. TextMeshPro를 쓸 경우 언어별
폰트 에셋을 만들고 대체 폰트(Fallback)로 연결합니다. 언어 선택 씬은 다섯 언어 이름을 한 화면에 동시에 보여주므로
모든 글자가 표시되는지 반드시 확인합니다.

9.2 다음 단계
1. 뼈대 만들기: 6개 씬 생성 및 Build Profiles 씬 목록 등록, GameSystems 와 SceneLoader , ScreenFader  구현
2. 흐름 검증: 각 씬에 임시 UI만 두고 로고부터 인게임 · 월드맵 복귀까지 전체 플로우가 끊김 없이 이어지는지 확인
3. 데이터 연결: 설정 · 세이브 서비스 구현, 최초 실행 판단과 이어하기 활성 조건 검증
4. 인게임 틀: 테스트 스테이지 1개를 Additive로 불러와 플레이어 · 카메라 배치 확인
5. 씬별 완성: 로고 연출, 언어 선택, 타이틀 메뉴, 로딩 화면, 월드맵 노드 순서로 실제 기능 구현
1차 완료 기준
최초 실행 시 로고 → 언어 선택 → 타이틀 → 로딩 → 월드맵 → 로딩 → 인게임 → 클리어 → 로딩 → 월드맵 순으로 진행
되고, 두 번째 실행부터는 언어 선택 없이 타이틀로 이어지며 이어하기가 활성화되면 1차 완료로 봅니다.
