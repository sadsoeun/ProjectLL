# LEAF & LEAP — 4지역 산호 해안 맵 제작 지시문

## 요청

첨부한 **산호 해안 콘셉트 원화와 리소스 시트**를 바탕으로, LEAF & LEAP에서 실제로 플레이할 수 있는 산호 해안 맵을 제작해 줘.

배경을 장식하는 데 그치지 말고, 기존 캐릭터의 이동·점프·전투 규칙에 맞춰 시작점부터 골인까지 연결되는 플랫포머 스테이지로 완성해 줘. 기존 맵툴과 레벨 데이터 구조를 먼저 확인하고, 그 구조에 맞춰 리소스와 레벨을 제작해야 해.

이번 작업의 기본 범위는 **4지역의 첫 번째 일반 스테이지 1개**다. 프로젝트의 ID 체계에서 사용 가능하다면 `W4_S1`을 사용해 줘. 이미 같은 ID나 제작 중인 맵이 있으면 상태를 확인한 뒤 이어서 작업하고, 기존 파일을 무조건 덮어쓰지 마.

## 1. 먼저 확인할 것

- 프로젝트의 기존 스테이지, 플레이어 컨트롤러, 카메라, 맵툴 사용 문서와 레이아웃 스키마를 읽어 줘.
- 캐릭터 크기, 이동 속도, 점프 높이·거리, 공중 제어, 충돌 판정, 재시작·체크포인트 규칙을 확인해 줘.
- 4지역 등록 여부와 스테이지 데이터베이스, 월드맵 노드, 씬 로딩 경로를 확인해 줘. 4지역이 이미 구현되어 있다고 가정하지 마.
- 원화에 있는 요소와 프로젝트에서 재사용할 수 있는 프리팹을 대조해 줘.
- 첨부 원화를 실제로 열어 보고 형태·색·비율을 기준으로 삼아 줘. 파일을 찾을 수 없으면 확인하지 못했다고 명시하고, 아래 명세로 진행할 수 있는 블록아웃부터 제작해 줘.
- 기존 지형 좌표계와 플레이 평면을 유지해 줘. 카메라나 이동 방식을 임의로 바꾸지 마.

확인 결과는 간단히 정리한 뒤 제작을 진행해 줘. 지원하지 않는 기능이나 없는 에셋을 이미 존재하는 것처럼 설명하지 마.

## 2. 비주얼 방향

**주제: 청록빛 바다, 밝은 모래사장, 산호 절벽과 해안 유적을 지나는 모험.**

- 밝은 모래색 지면, 청록·푸른 바다, 코랄 핑크와 주황 산호, 옅은 베이지 석회암을 중심으로 구성.
- 기존 게임과 어울리는 단순하고 명확한 실루엣, 로우폴리곤 형태, 셀식 명암 유지.
- 과도한 채도, 번쩍이는 재질, 사실적인 물 표현은 피하고 원화의 색감을 우선.
- 발판 윗면과 옆면의 색·명암을 구분하여 착지할 수 있는 면이 즉시 보이게 구성.
- 장식 산호와 위험 산호는 색만 바꾸지 말고 형태·움직임·배치로 구분.
- 플레이 구역은 또렷하게, 원경은 대비와 채도를 낮춰 캐릭터와 발판을 가리지 않게 구성.
- 초원·설산·용암 에셋을 그대로 놓고 색만 바꾼 맵처럼 보이지 않게 제작.

## 3. 플레이 흐름

목표 플레이 시간은 숙련되지 않은 플레이어 기준 **약 2~3분**으로 제안한다. 이는 설계 목표이며 실제 측정 결과와 구분해 보고해 줘.

| 구간 | 공간 구성 | 플레이 목적 |
|---|---|---|
| 시작 해변 | 넓은 모래 바닥, 낮은 바위, 조개와 작은 산호 | 시야 확보, 안전한 이동·점프 도입 |
| 산호 단구 | 높이가 다른 산호암 발판, 짧은 틈, 완만한 오르막 | 착지 지점을 읽는 기본 점프 |
| 해안 잔교 | 목재 발판과 바위섬, 지원되는 경우 이동 발판 | 타이밍 점프와 첫 체크포인트 |
| 산호 유적 | 돌기둥, 무너진 아치, 주 경로와 짧은 보상 경로 | 기존 적·기믹과 점프를 조합 |
| 마지막 전망대 | 넓은 도착 발판, 바다 전망, 명확한 골인 표식 | 마지막 도전 후 안전하게 클리어 |

### 배치 원칙

- 경로는 기존 카메라에서 자연스럽게 읽히도록 연결하고, 다음 착지 지점이 보이지 않는 필수 점프를 만들지 마.
- 처음 등장하는 기믹은 안전하게 익힌 뒤 다음 구간에서 난도를 높여 줘.
- 필수 점프는 확인된 최대 점프 거리·높이에 여유를 두고 설계해 줘. 단순히 최대 수치에 맞춘 점프를 연속 배치하지 마.
- 코인은 이동 경로와 점프 궤적을 안내하도록 배치하되, 안전한 경로처럼 보이는 함정 유도는 피해야 해.
- 특별 수집품은 기존 시스템에 맞춰 **3개**를 배치해 줘: 쉬운 발견 1개, 짧은 우회 1개, 선택적 도전 1개.
- 체크포인트는 긴 실패 반복을 줄이는 위치에 두고, 복귀 직후 적·가시·낙하에 맞지 않게 해 줘.
- 해수면을 보여주는 것과 수영 기능을 구현하는 것은 별개야. 기존 수영 시스템이 없다면 수영·잠수 구간을 필수 경로에 넣지 마.
- 바다 낙하는 기존 낙하·사망·복귀 규칙으로 처리하고, 수면 장식이 안전한 발판처럼 보이지 않도록 해 줘.
- 일반 스테이지에 보스전을 임의로 추가하지 마. 보스용 별도 맵은 이번 기본 범위에 포함하지 않아.

## 4. 제작할 지형·배경 리소스

### 바닥과 발판

- 모래 바닥: 직선, 끝단, 모서리, 단차 연결 모듈.
- 산호암 절벽: 상단 착지면, 절벽 벽면, 높이 변화용 모듈.
- 작은 바위섬과 독립 점프 발판.
- 목재 잔교: 직선 바닥, 끝단, 지지 기둥, 난간.
- 해안 유적: 돌바닥, 낮은 계단, 기둥, 무너진 아치.
- 기존 이동·낙하 발판이 지원되면 그 판정에 연결할 산호 해안 외형.

모듈 길이·높이·피벗은 기존 맵툴의 그리드와 프리팹 규칙에 맞춰 줘. 단순한 충돌체를 우선하고, 모듈 접합부에서 발이 걸리거나 틈으로 빠지지 않도록 해 줘.

### 3D 원경

- 가까운 바위섬, 중간 거리의 해안 절벽, 먼 섬과 낮은 산악 실루엣으로 깊이를 구성.
- 산호 군락, 작은 야자수 섬, 등대 또는 해안 유적을 시선 유도용 랜드마크로 사용.
- 원경의 섬·절벽·건축물은 **로우폴리곤 3D 메시**로 제작. 배경 일러스트 한 장으로 대체하지 마.
- 바다는 단순한 메시와 절제된 머티리얼 애니메이션으로 구성 가능.
- 플레이 평면 뒤에 배치하고 충돌체는 필요할 때만 추가. 전경 장식은 캐릭터를 가리지 않는 위치로 제한.

### 오브젝트·프랍

분기형 산호, 둥근 산호, 부채 산호, 조개, 불가사리, 해초, 표류목, 부서진 배 조각, 밧줄 기둥, 상자, 해안 표지판을 원화에 맞춰 제작하거나 재사용해 줘.

장식물과 상호작용 오브젝트는 분리해야 해. 장식 상자를 부술 수 있는 상자처럼 보이게 하거나, 배경 산호에 불필요한 충돌체를 붙이지 마.

## 5. 몬스터

기존 산호 해안 원화 시트에 몬스터가 있다면 그 디자인을 우선 사용해 줘. 아래는 원화에 해당 요소가 없을 때의 **제안 목록**이며, 기존 구현이 있다는 뜻은 아니야.

| 후보 | 시각적 특징 | 연결할 수 있는 역할 |
|---|---|---|
| 산호 게 | 넓은 집게, 낮고 둥근 몸 | 지상 순찰 |
| 소라게 | 큰 나선형 껍데기 | 느린 지상 적 |
| 복어 | 둥근 몸과 명확한 가시 | 접촉 위험 또는 주기적 위협 |
| 성게 | 작은 몸, 큰 방사형 가시 | 고정 장애물 |
| 해파리 | 반투명 몸과 짧은 촉수 | 기존 부유·왕복 이동 적 |
| 갈매기 | 단순한 날개와 부리 | 기존 비행 적 |
| 산호 슬라임 | 젤리 몸과 작은 산호 장식 | 기존 점프형 적 |
| 조개 포대 | 벌어지는 껍데기와 진주 | 기존 투사체 적 |

- 테마 리소스 구성은 8종까지 확장할 수 있게 하되, 이번 첫 맵에는 역할이 분명한 **3~4종**을 우선 배치해 줘.
- 현재 지원되는 행동을 확인한 후 외형을 연결해 줘. 외형만 바꾸고 새로운 전투 기능까지 구현했다고 말하지 마.
- 신규 AI가 필요하면 별도 구현 항목으로 표시하고, 우선 지원되는 행동으로 플레이 가능한 맵을 완성해 줘.
- 적의 공격 거리와 점프 구간을 겹칠 때 회피 공간을 확보하고, 화면 밖에서 예고 없이 공격하지 않게 해 줘.

## 6. 이펙트

- 해변 가장자리의 잔잔한 포말과 작은 물보라.
- 해초의 약한 흔들림, 원경의 느린 파도.
- 점프·착지 시 작은 모래 먼지.
- 수집품의 절제된 반짝임.
- 위험 요소와 공격에 필요한 예고·피격 이펙트.

플레이 정보를 가리는 큰 입자, 밝은 전면 발광, 잦은 화면 흔들림은 피해야 해. 신규 VFX보다 착지면과 적의 공격 예고가 잘 보이는 것이 우선이야. 기존 클리어 UI·금빛 연출은 재사용해 줘.

## 7. Blender 제작 규칙

Blender MCP가 연결되어 있다면 이를 사용해 리소스를 제작해 줘. 연결되어 있지 않으면 연결된 것처럼 작업 결과를 보고하지 마.

- 게임에서 보이는 실루엣을 우선하고, 작은 디테일을 과도하게 모델링하지 마.
- 바닥·벽·소품의 원점, 축 방향, 스케일을 기존 Unity 에셋과 일치시켜 줘.
- 정적인 지형과 리깅이 필요한 몬스터를 구분하고, 몬스터는 변형 부위를 고려해 제작.
- 공통 팔레트와 머티리얼을 재사용하고, 원경은 근경보다 단순한 메시로 구성.
- 모델과 충돌체를 구분하고, 동적 발판에는 기존 프로젝트가 사용하는 충돌 방식 적용.
- `.blend` 원본과 프로젝트에서 사용하는 교환 형식의 모델을 함께 제공. 임포트 후 단위·노멀·재질·피벗 확인.
- 정확한 폴리곤 예산은 기존 에셋과 목표 플랫폼을 먼저 확인해 정하고, 실제 삼각형 수를 결과물에 기록.

## 8. Unity와 맵툴 적용

프로젝트 내 실제 정의를 다시 읽고 다음 진입점을 활용해 줘.

- `Assets/_Project/Scripts/Editor/MapTool/StageMapAutomation.cs`
- `Assets/_Project/Scripts/Editor/MapTool/StageLayoutJson.cs`
- `StageLayoutData`, `StageLayoutValidator`, `StageLayoutBuilder`의 실제 정의와 사용 예제.
- 존재한다면 `Docs/map-tool-usage.md`.

현재 맵툴의 레이아웃 문서에는 시작점·골인·구간·블록·체크포인트·코인·특별 수집품·가시·이동 발판·적·낙하 발판·장식·가시 트랩·스위치·게이트·보스 항목이 있다. **항목의 존재만으로 모든 동작이나 4지역 지원이 완성되어 있다고 가정하지 말고**, 타입·필수 필드·등록 ID·빌더 처리를 확인해 줘.

1. 기존 맵 하나를 참고해 새 맵의 블록아웃 레이아웃 작성.
2. 시작점→체크포인트→골인의 경로와 수집품 위치부터 확정.
3. 레이아웃 JSON에 실제 스키마에서 지원하는 필드만 기록.
4. `MyGame.EditorTools.StageMapAutomation.ValidateFile(path)`로 검증.
5. 필요할 때 `NormalizeFile(path)`로 정규화하고 다시 검증.
6. `Build(path)`로 씬 생성 후 산호 해안 리소스·등록 정보를 연결.
7. 맵을 다시 빌드해도 필요한 지형과 장식이 유지되는지 확인. 빌더가 지우는 씬 내부 수작업에 의존하지 마.

권장 레이아웃 경로는 `Assets/_Project/Data/StageLayouts/W4_S1.json`이다. 실제 프로젝트 규칙과 충돌하면 기존 규칙을 우선하고 변경 경로를 보고해 줘.

## 9. 작업 방식과 유지 조건

- **마우스·키보드·브라우저 등 컴퓨터 화면 조작 자동화는 사용하지 마.** 파일 편집, 코드, CLI, 연결된 MCP/API로 작업해 줘.
- 기존 캐릭터 조작감, 카메라 규칙, 다른 지역의 맵, 저장 데이터는 임의로 변경하지 마.
- UI는 기존 검정·금빛 미감과 Noto Sans를 유지. 이번 작업에서 UI를 다시 디자인하지 마.
- 타이틀 캐릭터의 호흡 애니메이션은 계속 OFF 유지.
- 기획 설명이나 원화만 제공하고 맵 적용이 끝났다고 하지 마. 생성한 파일과 실제 적용 범위를 명확하게 보고해 줘.
- 검증을 통과시키려고 레벨 검증 규칙을 약화시키지 마.

## 10. 완료 조건과 제출물

- 산호 해안으로 읽히는 일관된 지형·프랍·3D 원경.
- 시작부터 골인까지 연결되는 일반 스테이지 1개.
- 기존 규칙에 맞는 체크포인트와 특별 수집품 3개.
- 필수 경로에서 도달 불가능한 점프, 충돌 틈, 적과 겹친 부활 위치가 없음을 확인.
- 새 맵의 월드맵 선택·로딩 연결 확인. 연결하지 못한 항목은 별도로 명시.
- 레이아웃 검증 결과, 컴파일 결과, 누락 프리팹·머티리얼 확인 결과 제출.
- 원본 모델, 임포트 모델, 프리팹, 레이아웃 JSON, 생성 씬의 실제 경로 제출.
- 전체 맵과 주요 구간의 코드 기반 프리뷰, 플레이 경로 설명 제공.
- 자동 검증·정적 렌더·실제 플레이 검증을 구분해서 보고. 실제로 플레이하지 않았다면 클리어 가능성을 실플레이로 검증했다고 표현하지 마.

먼저 프로젝트 구조와 원화를 확인한 뒤, **블록아웃 → 경로·충돌 확인 → 모델·원경 배치 → 적·수집품·이펙트 → 씬 연결·검증** 순서로 진행해 줘.
